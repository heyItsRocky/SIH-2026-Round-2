## Problem Description

Build an ultra-lightweight, highly accurate keyword spotting (KWS) model that runs locally on a low-power device. Upon detecting the keyword, the system must instantly and efficiently stream the subsequent audio to a remote Automated Speech Recognition (ASR) server with minimal data overhead and latency.

**Key Evaluation Metrics:**
- **Efficiency:** Model size (RAM/Flash footprint) and CPU usage during idle listening
- **Accuracy:** High true-positive rate for the keyword with near-zero false activations
- **Latency:** Time delta between keyword ending and cloud ASR receiving the audio stream

**Software & Framework Restrictions:**
- Open-source only — proprietary/closed-source/commercial voice-activation SDKs strictly prohibited
- Allowed: TensorFlow Lite for Microcontrollers, PyTorch Mobile, or similar TinyML frameworks
- No pre-trained global keywords (e.g., "Hey Google", "Alexa") — must train on a custom keyword

**Hard Constraints:**
- Edge app must run in **<256KB RAM** and **<10% CPU** while idling in continuous listening mode
- Heavy or uncompressed pre-trained transformers are disqualified
- Evaluated on physical low-power microcontrollers (e.g., Raspberry Pi or ESP32)

## Solution Approach

Hybrid edge-cloud voice activation: an ultra-lightweight TinyML keyword-spotting model runs continuously on an ESP32, and only upon detecting the custom wake word does it stream the subsequent audio to a remote ASR server.

```
ESP32 (Edge)                          Cloud / Pi 4 (ASR)
┌──────────────────────┐              ┌──────────────────────┐
│ INMP441 I2S Mic      │              │ Vosk / Whisper ASR   │
│        │             │              │        ▲             │
│        ▼             │   wake word  │        │             │
│ MFCC Feature Extract │──detected──► │  Audio Stream (Opus) │
│        │             │              │        │             │
│        ▼             │              │        ▼             │
│ TFLite Micro KWS     │              │  Transcription →     │
│ (custom keyword)     │              │  Command Execution   │
└──────────────────────┘              └──────────────────────┘
```

**Pipeline:**
1. **Continuous listening** on ESP32 — INMP441 mic → MFCC features → TFLite Micro KWS model
2. **Wake word detection** — custom-trained keyword (e.g., "ULTRON") with near-zero false positives
3. **Audio streaming** — on detection, stream subsequent audio (Opus-compressed) over WiFi to ASR server
4. **Cloud ASR** — Pi 4 (or remote server) runs Vosk/Whisper for full speech recognition
5. **Status feedback** — NeoPixel + OLED show listening/detected/streaming states

## Key Differentiators (if pursued)

| PS Keyword | How We Address It |
|---|---|
| Ultra-lightweight | TFLite Micro quantized model, <256KB RAM target |
| Low latency | Edge wake-word detection → instant stream, no cloud round-trip for wake |
| Custom keyword | Train on team-specific keyword (e.g., "ULTRON"), not generic assistants |
| Open-source only | TFLite Micro + Vosk/Whisper, no proprietary SDKs |
| Edge-cloud hybrid | ESP32 handles wake, Pi 4/cloud handles heavy ASR |

**Security angle (differentiation):** Pair with SENTINEL narrative — voice-authenticated edge device where the wake word doubles as a security gate (voice biometrics on top of KWS). This is the strongest differentiator vs. generic KWS submissions.
